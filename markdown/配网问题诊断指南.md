# BLE Mesh 配网问题诊断指南

## 问题现象
配网流程卡在"发送配网邀请"，无法继续。

## 已修复的问题

### Android 端修复
**问题**: `BleConnectionManager` 中的 `isServiceDiscoveryComplete` 标志在每次连接时没有被重置。

**影响**: 
- 第一次连接 Proxy 节点后，标志被设置为 true
- 之后连接未配网设备时，即使通知启用成功，`onServicesDiscovered()` 回调也不会被调用
- 配网流程无法启动

**修复**: 在 `BleConnectionManager.kt` 的两个 `connect()` 方法开始时添加：
```kotlin
isServiceDiscoveryComplete = false
```

**验证**: 编译并安装最新版本的 APK

## 诊断步骤

### 1. 验证 Android 端修复是否生效

运行诊断脚本：
```bash
bash diagnose_provision.sh
```

脚本会自动检查：
1. 设备连接状态
2. 应用安装状态
3. Mesh 网络加载
4. NetKey 和 AppKey 存在
5. 配网流程各个步骤

### 2. 手动检查关键日志

启动应用并进入配网流程，然后查看日志：

```bash
adb -s 4e456a52 logcat -d | grep -E "(配网|onServicesDiscovered|identifyNode)"
```

**期望看到的日志**:
```
服务发现完成，开始配网流程
=== 配网前检查 ===
网络名称: 小米9
NetKeys: 1
AppKeys: 1
调用 identifyNode: UUID=xxx
=== 配网状态变化 ===
=== 发送配网 PDU ===
PDU 长度: 3
配网 PDU 已发送
```

**如果看不到 "服务发现完成，开始配网流程"**:
- 说明 Android 端修复未生效
- 重新编译并安装 APK

**如果看到 "服务发现完成" 但没有后续日志**:
- 说明配网前检查失败
- 检查网络是否有 NetKey 和 AppKey

### 3. 检查固件端响应

查看是否收到设备响应：

```bash
adb -s 4e456a52 logcat -d | grep "收到 BLE 数据"
```

**如果没有收到任何响应**:
- 问题在固件端
- 固件未正确处理配网邀请

**如果收到响应但配网仍然卡住**:
- 检查响应内容是否正确
- 可能是协议不匹配

## 固件端可能的问题

### 1. 配网功能未正确启用

检查固件配置：
```c
// app_mesh_config.h
#define CONFIG_BLE_MESH_PB_GATT  1  // 必须为 1
```

### 2. 配网回调未正确实现

检查 `app.c` 中的配网回调：
```c
static const struct bt_mesh_prov app_prov = {
    .uuid = dev_uuid,
    .link_open = link_open,
    .link_close = link_close,
    .complete = prov_complete,
    .reset = prov_reset,
};
```

### 3. 固件未响应配网邀请

通过串口查看固件日志：
```bash
# 使用串口工具连接 COM3，波特率 115200
# 或使用 Python 脚本
python tools/serial_monitor.py
```

**期望看到的固件日志**:
```
Link opened via PB-GATT (Proxy Connection)
Device connected for provisioning
```

**如果没有看到这些日志**:
- 固件端没有收到配网请求
- 可能是 BLE 连接问题
- 检查固件的 BLE 协议栈是否正常

### 4. 固件端 BLE 服务未正确注册

检查固件是否正确注册了 Provisioning Service：
- Service UUID: `00001827-0000-1000-8000-00805f9b34fb`
- Data In UUID: `00002adb-0000-1000-8000-00805f9b34fb`
- Data Out UUID: `00002adc-0000-1000-8000-00805f9b34fb`

## 常见问题

### Q1: 配网时设备立即断开连接
**原因**: 固件端可能在处理配网数据时崩溃或重启
**解决**: 检查固件日志，查看是否有异常

### Q2: 配网卡在某个特定步骤
**原因**: 协议不匹配或固件未正确实现某个配网步骤
**解决**: 对比 nRF Mesh 库的配网流程和固件实现

### Q3: 配网完成但设备无法通信
**原因**: AppKey 未正确添加或绑定
**解决**: 检查配网完成后的配置流程

## 下一步行动

1. **运行诊断脚本**: `bash diagnose_provision.sh`
2. **查看诊断结果**: 确定问题在 Android 端还是固件端
3. **如果是 Android 端**: 确认已安装最新版本 APK
4. **如果是固件端**: 通过串口查看固件日志，确认固件是否收到配网请求
