# BLE Mesh 自动连接策略

## 触发时机

进入设备控制界面（`DeviceDetailActivity`）后，延迟 500ms 自动开始连接。

## 连接流程

```
进入设备详情页
    │
    ▼
延迟 500ms
    │
    ▼
构建 MAC 优先级列表
    │
    ├── (1) 目标设备 MAC ─── 当前设备卡片的 BLE 地址
    ├── (2) 同组设备 MAC ─── 与当前设备同分组的其他设备
    └── (3) 其他已配网 MAC ── 所有已配网过的设备
    │
    ▼
依次尝试连接（每个 5s 超时）
    │
    ├── 成功 → 保存代理地址 → 开始目标监测
    │
    └── 全部失败 → 提示"所有设备均无法连接"
```

## MAC 优先级列表构建

```
优先级 1: 目标设备 MAC
  └─ 来源: DeviceRepository 中当前设备 (device.address) 的 bluetoothMac
  └─ 作用: 直接连接目标设备，无需扫描

优先级 2: 同组设备 MAC
  └─ 来源: 当前设备所属分组中的其他成员
  └─ 筛选: device.groupIds → groupRepository → memberDeviceIds → getDeviceMac()
  └─ 作用: 目标不在线时，改连同组设备

优先级 3: 其他已配网设备 MAC
  └─ 来源: DeviceRepository 中所有设备（排除当前设备和同组设备）
  └─ 作用: 同组无设备在线时，连接任意可用 Mesh 节点
```

## 连接尝试

- 每个 MAC 地址按优先级顺序逐一尝试
- 每个 MAC 超时时间: **5 秒**
- 连接成功: 保存到代理地址历史（`SharedPreferences`），触发 `onConnected` 回调
- 连接失败/超时: 延迟 500ms 后尝试下一个
- 全部失败: 调用 `onAllFailed` 回调

## 目标监测

连接成功后，开启 BLE 扫描监测目标设备：

```
连接成功（任意设备）
    │
    ▼
开启 BLE 扫描（startBleScan）
    │
    ▼
持续监测扫描结果
    │
    ├── 目标设备 MAC 出现 → 停止监测
    │   ├── 已连接该设备 → 忽略
    │   ├── 已连接其他设备 → 断开 → 延迟 500ms → 连接目标
    │   └── 未连接 → 直接连接目标
    │
    └── 目标未出现 → 继续扫描
```

- 目标监测使用 `Observer<List<ScanResult>>` 观察 `viewModel.scannedDevices`
- 目标设备通过 MAC 地址匹配（忽略大小写）
- 页面销毁时通过 `stopTargetMonitoring()` 清理 observer 和停止扫描

## 注意事项

1. **MAC 地址来源**: `DeviceRepository` 中 `MeshDevice.bluetoothMac` 字段（配网时保存），回退到 `SharedPreferences`
2. **MAC 大小写**: nRF 库返回的大写（`D4:8A:FC:XX:XX:XX`），比较时使用 `equals(ignoreCase=true)`
3. **断开重连间隔**: 切换设备时断开旧连接后延迟 500ms 再连接，避免 BLE 栈竞争
4. **目标监测扫描**: 始终在后台扫描，一旦目标出现立即切换；切换后不再扫描
5. **按钮状态**: 自动连接过程中 `btnAutoConnect` 禁用；全部失败后重新启用
