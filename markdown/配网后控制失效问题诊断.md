# 配网后控制失效问题诊断

## 问题描述

**流程**：
1. ✅ 配网成功
2. ✅ 绑定 AppKey 成功  
3. ✅ 导入 nRF Mesh 的 JSON 配置
4. ❌ 控制命令不起作用

## 根本原因

### AppKey 不匹配导致消息解密失败

```
配网时的流程:
1. 你的 app 配网设备
   └── 使用 app 当前数据库中的 AppKey (假设是 AAAA)
   
2. 绑定模型到 AppKey
   └── 设备保存: Generic Level Model → AppKey AAAA
   
3. 导入 nRF Mesh 的 JSON
   └── app 数据库被替换
   └── 新的 AppKey: BBBB (来自 nRF Mesh)
   
4. 发送控制命令
   └── 使用新的 AppKey BBBB 加密消息
   └── 设备用 AppKey AAAA 解密
   └── ❌ 解密失败 → 设备忽略消息
```

## 详细分析

### 1. 配网时使用的 AppKey

```kotlin
// MeshViewModel.kt - configureNode()
private fun configureNode(address: Int) {
    val network = MeshState.meshNetWork ?: return
    val appKey = network.appKeys.firstOrNull() ?: return  // ← 使用当前数据库的 AppKey
    val netKey = network.netKeys.firstOrNull() ?: return
    
    // 添加 AppKey 到设备
    MeshState.meshManagerApi.createMeshPdu(
        address, 
        ConfigAppKeyAdd(netKey, appKey)  // ← 设备保存这个 AppKey
    )
    
    // 绑定模型
    bindModels(address)
}

private fun bindModels(address: Int) {
    val appKey = network.appKeys.firstOrNull() ?: return  // ← 同一个 AppKey
    
    // 绑定 Generic Level Model (0x1002) 到 AppKey
    MeshState.meshManagerApi.createMeshPdu(
        address, 
        ConfigModelAppBind(elementAddress, 0x1002, appKey.keyIndex)
    )
}
```

**结果**：设备的 Generic Level Model 绑定到 **配网时的 AppKey**

### 2. 导入 JSON 后的 AppKey

```kotlin
// MeshViewModel.kt - importMeshNetwork()
fun importMeshNetwork(jsonData: String) {
    try {
        MeshState.meshManagerApi.importMeshNetworkJson(jsonData)
        // ↑ 这会替换整个数据库，包括 AppKey
    } catch (e: Exception) {
        MeshState.statusText.postValue("导入异常: ${e.message}")
    }
}
```

**结果**：app 数据库中的 AppKey 被替换为 **nRF Mesh 的 AppKey**

### 3. 发送控制命令时

```kotlin
// MeshViewModel.kt - sendBrightness()
fun sendBrightness(address: Int, brightness: Int) {
    val network = MeshState.meshNetWork ?: return
    val appKey = network.appKeys.firstOrNull() ?: return  // ← 使用新的 AppKey
    
    val message = GenericLevelSetUnacknowledged(appKey, level, tid)
    MeshState.meshManagerApi.createMeshPdu(address, message)
    // ↑ 消息用新的 AppKey 加密
}
```

**结果**：消息用 **nRF Mesh 的 AppKey** 加密

### 4. 设备端解密

```c
// 固件端 - gen_level_set_unack()
static void gen_level_set_unack(...) {
    // 设备尝试用绑定的 AppKey 解密消息
    // 绑定的 AppKey = 配网时的 AppKey
    // 收到的消息 = 用 nRF Mesh 的 AppKey 加密
    // ❌ AppKey 不匹配 → 解密失败 → 忽略消息
}
```

## 解决方案

### 方案 1：先导入 JSON，再配网（推荐）

**正确流程**：
```
1. 导入 nRF Mesh 的 JSON
   └── app 数据库使用 nRF Mesh 的 NetKey 和 AppKey
   
2. 配网设备
   └── 使用 nRF Mesh 的 AppKey 配网
   
3. 绑定模型
   └── 设备保存 nRF Mesh 的 AppKey
   
4. 发送控制命令
   └── 使用 nRF Mesh 的 AppKey 加密
   └── 设备用相同的 AppKey 解密
   └── ✅ 解密成功 → 执行命令
```

**操作步骤**：
1. 打开你的 app
2. 进入设置 → 导入 Mesh 配置
3. 选择 nRF Mesh 导出的 JSON
4. **重新配网所有设备**（重要！）
5. 测试控制命令

### 方案 2：重新绑定 AppKey

如果不想重新配网，可以尝试重新绑定 AppKey：

```kotlin
// 添加到 MeshViewModel.kt
fun rebindAppKey(address: Int) {
    val network = MeshState.meshNetWork ?: return
    val node = network.getNode(address) ?: return
    val appKey = network.appKeys.firstOrNull() ?: return
    
    Log.d("MeshApp", "重新绑定 AppKey 到设备 0x${address.toString(16)}")
    
    // 先添加 AppKey 到设备（如果设备已有，会忽略）
    val netKey = network.netKeys.firstOrNull() ?: return
    MeshState.meshManagerApi.createMeshPdu(
        address, 
        ConfigAppKeyAdd(netKey, appKey)
    )
    
    // 延迟后绑定模型
    android.os.Handler(android.os.Looper.getMainLooper()).postDelayed({
        node.elements?.forEach { element ->
            element.value.meshModels?.forEach { (modelId, _) ->
                if (listOf(0x1002, 0x1100, 0x1200, 0x1206).contains(modelId)) {
                    try {
                        Log.d("MeshApp", "绑定模型 0x${modelId.toString(16)} 到 AppKey")
                        MeshState.meshManagerApi.createMeshPdu(
                            address, 
                            ConfigModelAppBind(element.value.elementAddress, modelId, appKey.keyIndex)
                        )
                    } catch (e: Exception) {
                        Log.e("MeshApp", "绑定失败: ${e.message}")
                    }
                }
            }
        }
    }, 1000)
}
```

**使用方法**：
```kotlin
// 在设备详情页面添加"重新绑定"按钮
viewModel.rebindAppKey(deviceAddress)
```

### 方案 3：不导入 JSON，导出你的配置给 nRF Mesh

**流程**：
```
1. 在你的 app 中配网所有设备
2. 导出配置 JSON
3. 在 nRF Mesh app 中导入你的配置
4. 两个 app 使用相同的 NetKey 和 AppKey
```

### 3. 添加配置一致性检查

```kotlin
fun checkConfigConsistency(address: Int): Boolean {
    val network = MeshState.meshNetWork ?: return false
    val node = network.getNode(address) ?: return false
    
    // 检查节点的 AppKey 是否与当前网络的 AppKey 一致
    val networkAppKey = network.appKeys.firstOrNull() ?: return false
    val nodeAppKeys = node.addedAppKeys
    
    val hasMatchingKey = nodeAppKeys.any { it.keyIndex == networkAppKey.keyIndex }
    
    if (!hasMatchingKey) {
        Log.w("MeshApp", "警告：设备 0x${address.toString(16)} 的 AppKey 与网络不一致")
        return false
    }
    
    return true
}
```

## 总结

**问题根源**：配网时使用的 AppKey 和导入 JSON 后的 AppKey 不一致

**解决方案**：
1. **推荐**：先导入 JSON，再重新配网所有设备
2. **备选**：重新绑定 AppKey 到已配网的设备
3. **备选**：不导入 JSON，导出你的配置给 nRF Mesh

**关键点**：
- 配网时设备保存的 AppKey 必须与发送控制命令时使用的 AppKey 一致
- 导入 JSON 会替换整个数据库，包括 NetKey 和 AppKey
- 已配网的设备不会自动更新 AppKey，需要重新配网或重新绑定
